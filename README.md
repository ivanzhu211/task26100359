# task26100359

本地密钥保管库（Go + SQLite），支持主密钥在线轮换。

## 设计

- 每把密钥：UUID + 32 字节随机材料，材料用主密钥做 AES-256-GCM 加密后存 `keys` 表（`id, gen, nonce, ct`）。
- 主密钥：口令经 PBKDF2-SHA256（600000 次迭代，随机 salt）派生；口令不落盘。`meta` 表存 salt、迭代次数、以及用主密钥加密固定常量得到的 verifier，Open 时用它校验口令。
- 每行带代际号 `gen`：当前代用当前主密钥解密，轮换期间出现的新一代用新主密钥解密。

## 轮换（RotateMaster）

1. 新口令 + 新 salt 派生新主密钥；在一个小事务里写入 `rot_*`（新 salt/verifier/新代际号，以及用**新**主密钥加密的旧主密钥 `rot_recovery`，供崩溃恢复续跑用）。
2. 分批（256 行一个事务）把 `gen=旧` 的行解密、用新主密钥重新加密、改成新代。期间 CreateKey 直接写新代，GetMaterial 按行的代际选密钥，DestroyKey 直接删除——三者都不被轮换阻塞，单次阻塞时间上界是一个小批次事务。
3. 收尾事务：确认没有旧代行残留后，把 `rot_*` 提升为正式元数据并删除（含 `rot_recovery`），库里只剩新口令有效。

## 崩溃恢复

轮换期间被 kill -9 后，调用方先用新口令 Open、失败再用旧口令：

- 轮换状态存在 → 只有新口令能打开：用 `rot_recovery` 解出旧主密钥，把剩余旧代行续跑完（roll-forward），Open 返回时轮换已结束、只剩一个有效口令。
- 轮换状态不存在 → 要么从未开始（旧口令有效），要么已收尾（新口令有效）。

回滚不可能也不需要：已转换的行只能用新主密钥解密，而旧口令派生不出它；调用方固定先试新口令，续完必然成功。

## 测试

- `TestRotateConcurrent`：预置 10 万把密钥，轮换期间多个 goroutine 并发 Create/Get/Destroy，任何一次读错即失败；轮换后用轮换前截获的主密钥逐条试解全部密文（有一条解开即失败），再用当前主密钥解出全部密文并校验无已销毁密钥的材料重现。
- `TestCrashRecovery`：子进程跑 RotateMaster，随机时刻 kill -9，重复 14 轮（含恢复后紧接着的下一轮轮换又被杀、轮换完成后才被杀等情形）；每轮子进程按"新口令→旧口令"顺序 Open 并逐字节校验 2 万把密钥，最后父进程再全量校验。

运行：`go test -v -timeout 900s .`
